Public scope and verification boundary

The public repository is a collection of source fragments, assets, SQL, documentation, and screenshots. It lacks a complete CMake/Unity project, several protocol headers, and components referenced by the deployment guide. The current files alone do not substantiate one-click builds, production readiness, or App Store approval.

05 / FAQ

Frequently asked questions

Is this a complete runnable tournament project?

No. The public files need additional headers, protocol definitions, build configuration, client project files, and runtime configuration.

Which tournament features are evidenced?

Screenshots evidence event lists, registration state, countdowns, training events, news/video, and saved hands. The API document adds tournament-list and registration message examples.

Which server technologies are evidenced?

The committed source directly supports C++, Tars-style proxies, MySQL access, and serialized messaging. Redis, Java, and Unity are mentioned in deployment notes and require the complete project to confirm.

Can I use it commercially?

Resolve the conflicting license statements first, then verify rights for product branding, event media, and any separately delivered complete source.

Evaluate the repository from its evidence

Read the source map, API documentation, and scope boundary before defining the missing files and test plan.
